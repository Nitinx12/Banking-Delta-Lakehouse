Daily lakehouse · reproducible by design

From three source systems to trusted Delta marts.

A local-first PySpark pipeline lands MySQL, MongoDB and Databricks public data into PostgreSQL, transforms it through medallion layers, gates every layer with SQL data quality suites, then publishes eight marts to Databricks Delta.

Extract

Three systems, one deterministic order

Extraction runs MongoDB first, then Databricks public, then MySQL. Each attempt has three tries, 30-second backoff and a 300-second timeout.

MySQL

5 full

Full loads of accounts, branches, cards, customers and employees.

MongoDB

2 incremental

support_tickets and card_transactions re-read by _id.

Databricks public

3 incremental

loans, loan_payments and transactions re-read by created_at.

Layers

Medallion layers with explicit owners

Landing, staging, core and mart are written only by their owners. SQL procedures transform inside PostgreSQL; Databricks receives published marts.

raw

10 tables

PySpark lands source snapshots with run tags. MySQL full loads truncate and insert atomically; incremental sources re-read a bounded window.

staging

10 tables

Stored procedures conform types, normalise keys and prepare SCD2 hashes for core loads.

core

7 dims · 4 facts

Dimensions use SCD2; facts store measures as NUMERIC(18,2) and timestamps as timestamptz.

mart

8 marts

Business tables are exported to Parquet, staged in a UC volume and written to Delta/core and Delta/mart.

Quality

44 checks across four gates

Every layer has a SQL DQ suite in tests/data-quality/. A critical failure blocks publish; watermarks advance only inside the load transaction.

10raw checks
10staging checks
13analytics checks
11mart checks
Never mixed. Full MySQL loads have no watermark. Truncate and insert are atomic so readers never see an empty table, and every load is safe to run twice with the same input.

Watermark behaviour

Date watermarks re-read the last N months with --lookback or PUBLISH_LOOKBACK_MONTHS. Timestamp watermarks use strict >. Missing columns are added automatically.

Stack

Local-first, contract-driven, publish-last

Python 3.13 and PySpark 3.5.x do the movement, PostgreSQL procedures do the transformation, SQL suites gate each layer, and Databricks Delta is the published surface.

Transform

SQL procedures

Explicit column lists, advisory locks, no procedure commits and counts returned through OUT parameters.

Serve

Delta + Streamlit

Published marts land in Databricks core/mart; reporting and Streamlit consume the curated tables.

Publish is a full overwrite

corrected in docs

The current implementation exports each mart to Parquet, stages it in a UC volume and runs an overwrite against Delta. An empty where forces the full refresh; it is not a keyed MERGE.
