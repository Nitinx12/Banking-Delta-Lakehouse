# 📊 Reporting System Technical Documentation

This directory contains the automated reporting engine responsible for generating high-fidelity PDF reports that monitor the health, performance, and quality of the Banking Delta Lakehouse.

## 🎯 Purpose
The reporting system transforms raw pipeline execution logs and metrics into executive-level PDFs. It provides three primary report types:
- **Daily Report**: A snapshot of the most recent warehouse run, focusing on freshness and DQ.
- **Weekly Report**: A trend analysis of performance and failure rates over 7 days.
- **Incident Report**: A deep-dive into a specific failed `run_id` to facilitate root-cause analysis.

---

## ⚙️ Architectural Workflow
The report generation follows a strictly decoupled **Collect $\rightarrow$ Analyze $\rightarrow$ Render $\rightarrow$ Compile** pipeline.

### 1. Data Collection (`scripts/collect.py`)
Extracts raw execution data from the PostgreSQL metadata store and Databricks logs. It populates a `context.json` file which serves as the single source of truth for the rendering engine.

### 2. Metric Analysis (`scripts/kpis.py`, `scripts/severity.py`)
- **KPI Calculation**: Computes success rates, average durations, and row-count variances.
- **Severity Engine**: Assigns a severity level (`INFO`, `WARN`, `CRITICAL`) to the report based on SLO breaches defined in `config/slo.yaml`.

### 3. Visualization (`scripts/charts.py`)
Generates a suite of PDF figures using Python plotting libraries. These are saved in `figures/` and embedded into the LaTeX document:
- `dq_heatmap.pdf`: Visualizes Data Quality failures across tables.
- `trend_failures.pdf`: Tracks failure frequency over time.
- `task_timeline.pdf`: Gantt-style view of pipeline execution.

### 4. Template Rendering (`scripts/render.py`)
Uses **Jinja2** to inject the analyzed data into LaTeX templates (`chapters/*.tex.j2`). 
- The logic handles conditional rendering (e.g., only showing the Incident section if a failure occurred).
- TikZ code is dynamically generated via `scripts/flow.py` to create the pipeline flow diagram.

### 5. LaTeX Compilation (`scripts/compile.py`)
Invokes `xelatex` (via `latexmkrc`) to produce the final PDF. It uses custom fonts (`fonts/`) and a project-specific style file (`template/bankingreport.sty`) to ensure consistent branding.

## 🛠 Usage & Automation

### CLI Commands
All operations are orchestrated via the root `Makefile`:

- **Standard Reports**
  - `make report`: Generate today's daily report.
  - `make report-weekly`: Generate the weekly summary.
  - `make report-incident RUN=123`: Debug a specific run.

- **Developer & CI Tools**
  - `make report-fixture`: Test the rendering engine using static JSON fixtures.
  - `make report-docker`: Run the entire pipeline inside a container to avoid local TeX installation issues.

### Quality Gates
Reports are validated during CI:
- **Page Budget**: Checks that reports don't exceed length limits.
- **Log Analysis**: Scans LaTeX logs for `Overfull \hbox` or critical errors.
